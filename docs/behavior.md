# Freezing behavior and Chrome limitations

- Each Chrome window has its own selected tab. The extension starts an inactivity deadline when an eligible tab becomes a background tab. Already-open background tabs start a fresh interval when the extension first sees them. A different main document, including one created by reloading the same URL, starts a fresh interval when the tab becomes eligible again. Moving a tab to another window or returning from an excluded state also starts a fresh interval. `pushState`, `replaceState`, and fragment changes preserve the deadline while the tab remains eligible. Exclusions use the current URL. [Chrome webNavigation](https://developer.chrome.com/docs/extensions/reference/api/webNavigation)
- The extension handles completed HTTP and HTTPS pages. It skips the Chrome Web Store, Chrome internal pages, local files, extension pages, discarded tabs, and tabs in Split View. Excluded hostnames also cover their subdomains. The pinned and audio exclusions are configurable and enabled by default.
- A Manifest V3 worker stores each deadline's main document ID in session storage and uses a shared Chrome alarm. On restart, it checks each pending deadline against the current document. It also checks the main document before and after freezing. If Chrome temporarily cannot identify the document, the extension defers the tab and retries through the shared alarm. Chrome can deliver alarms late, particularly after device sleep. A full browser restart starts new deadlines. [Chrome alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms)
- The extension sends `Page.setWebLifecycleState` with `frozen` through `chrome.debugger` and keeps its session while the page is frozen. It detaches directly when its freeze attempt is canceled before dispatch, including when Chrome has already frozen the page. The extension records that a freeze may run before it sends the command. If the command may have run, it requests `active` before detaching, including after a worker restart. After a successful thaw, a failed detach is retried on its own. Chrome displays a debugger banner. If DevTools already holds a session or Chrome rejects the attachment, the extension skips that inactivity interval. If the browser ends the extension's session while the tab is hidden, selecting the tab lets Chrome thaw it. [Chrome debugger](https://developer.chrome.com/docs/extensions/reference/api/debugger)
- Chrome exposes selection and CDP freezing as separate operations. The extension checks selection immediately before and after the freeze command and promptly resumes the page if a switch overtakes the command. A switch in that gap can briefly freeze a newly selected tab. In a controlled test on Chrome 158, a deliberately late command also left the page reporting itself hidden after JavaScript resumed. Switching away and back restored visibility. An absolute guarantee against this race requires a browser-side selection check. [Chromium's lifecycle command implementation](https://chromium.googlesource.com/chromium/src/+/refs/tags/158.0.8127.36/content/browser/devtools/protocol/page_handler.cc)
- Freezing pauses freezable page tasks, including the test page's interval, and retains the loaded document in memory. Chrome can still independently discard tabs under memory pressure, and websites can change their own state in response to lifecycle events. The CDP command is experimental and behavior may change in future Chrome versions. [Page Lifecycle API](https://developer.chrome.com/docs/web-platform/page-lifecycle-api) · [CDP lifecycle command](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-setWebLifecycleState)
